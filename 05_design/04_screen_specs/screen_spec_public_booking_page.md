## Screen Name

หน้าจองนัดสาธารณะ (Public Booking Page) — route `/:businessSlug`

## Purpose

ให้ลูกค้าจองนัดกับธุรกิจได้เองครบทุกขั้นตอนในหน้าเดียว (multi-step ต่อเนื่อง) โดยไม่ต้องสร้างบัญชี ไม่ต้องโทรหาร้าน และไม่ต้องรอเจ้าหน้าที่รับสาย — เป็นหน้าที่แทนที่การนัดผ่านโทรศัพท์/สมุดจดแบบเดิม

## Primary Users

- **Customer** — ผู้ใช้หลัก เข้าถึงผ่านลิงก์/QR code ที่ธุรกิจแจก มักเปิดจากมือถือ ไม่มีบัญชีผู้ใช้
- **Business Owner / Staff** (ทางอ้อม) — ไม่ได้ใช้หน้านี้จัดการนัด แต่เป็นผู้แจกลิงก์นี้ให้ลูกค้า และควรเห็นหน้าเดียวกันนี้เวลาตรวจสอบว่าลูกค้าเห็นข้อมูลอะไรบ้าง

## Data Shown

- ชื่อธุรกิจ โลโก้ (ถ้ามี) และเวลาทำการ
- รายการบริการที่ยังเปิดใช้งาน (`isActive = true`) พร้อมชื่อ ระยะเวลา และราคา
- รายการพนักงานที่ให้บริการที่เลือกได้ (กรองจาก service assignment) รวมตัวเลือก "คนไหนก็ได้"
- ช่วงเวลาว่างของวันที่เลือก คำนวณสดจากเวลาทำการ + booking ปัจจุบัน + ระยะเวลาบริการที่เลือก (ไม่ cache เกิน 60 วินาที — อ้างอิง [BR-005](../../04_requirements/business_rules.md#br-005--availability-ต้องคำนวณจากเวลาทำการ--booking-ที่มีอยู่เสมอ))
- ฟอร์มกรอกชื่อและเบอร์โทร (หรืออีเมล)
- สรุปนัดก่อนยืนยัน (บริการ / พนักงาน / วันเวลา / ราคา)

## Main Actions

1. เลือกบริการ
2. เลือกพนักงาน หรือ "คนไหนก็ได้"
3. เลือกวันที่ → ดูช่วงเวลาว่าง → เลือกช่วงเวลา
4. กรอกชื่อและเบอร์โทร
5. ตรวจสรุปนัด แล้วกด "ยืนยันการจอง"
6. (หลังยืนยันสำเร็จ) ไปหน้ายืนยัน ซึ่งมีลิงก์ไปหน้าจัดการนัดในอนาคต

## Empty State

| สถานการณ์ | สิ่งที่แสดง |
|---|---|
| ธุรกิจยังไม่มีบริการที่เปิดใช้งานเลย | ข้อความ "ร้านยังไม่เปิดให้จองในขณะนี้ กรุณาติดต่อร้านโดยตรง" พร้อมเบอร์โทรร้าน (ถ้ามีในโปรไฟล์) — ไม่แสดงฟอร์มจอง |
| วันที่เลือกไม่มีช่วงเวลาว่างเหลือ (เต็มหมด/ร้านปิด) | ข้อความ "ไม่มีเวลาว่างในวันนี้" พร้อมปุ่มเลื่อนไปวันถัดไปที่มีเวลาว่าง โดยไม่ต้องให้ลูกค้ากดเลือกวันไปเรื่อย ๆ เอง |

## Error State

| สถานการณ์ | สิ่งที่แสดง |
|---|---|
| ช่วงเวลาที่เลือกถูกจองไปแล้วตอนกดยืนยัน (double booking) | ข้อความ "ช่วงเวลานี้ถูกจองไปแล้ว ลองเลือกเวลาอื่นดูนะครับ" พร้อม refresh รายการเวลาว่างทันที ข้อมูลชื่อ/เบอร์โทรที่กรอกไว้ไม่หาย (อ้างอิง [BR-001](../../04_requirements/business_rules.md#br-001--ห้ามจองชนกัน-double-booking), [Booking Flow §4](../01_user_flows/booking_flow.md#4-edge-case-double-booking-ระหว่างกรอกฟอร์ม)) |
| เบอร์โทรกรอกผิดรูปแบบ | inline error ใต้ช่องกรอกทันที ไม่ต้องรอกดยืนยันทั้งฟอร์ม |
| เครือข่ายขัดข้องตอนกดยืนยัน | แสดงปุ่ม "ลองใหม่" การกดซ้ำต้องไม่สร้าง booking สองรายการ (idempotent submit) |
| businessSlug ไม่มีอยู่จริง | หน้า 404 แบบสุภาพ "ไม่พบร้านที่ค้นหา" ไม่ใช่ error ทางเทคนิค |

## Permission / Privacy Notes

- ไม่ต้อง login — ลูกค้าไม่มีบัญชีเต็มรูปแบบใน MVP (อ้างอิง [Permission Requirements — Roles](../../04_requirements/permission_requirements.md#roles))
- หลังจองสำเร็จ ระบบสร้าง token เฉพาะของ booking นั้นสำหรับใช้จัดการนัดในอนาคต ไม่ผูกกับบัญชีถาวร
- หน้านี้ต้อง**ไม่แสดง**ข้อมูลนัดของลูกค้ารายอื่น เบอร์โทร/อีเมลของพนักงาน หรือรายละเอียดภายในธุรกิจอื่นใดนอกจากชื่อพนักงานและบริการที่เปิดสาธารณะ
- ควรมี rate limiting ที่ระดับ API เพื่อลด spam booking จากบอท (เช่น จำกัดจำนวนการจองต่อเบอร์โทรต่อชั่วโมง)

## Acceptance Criteria

- Given ลูกค้าเปิดลิงก์จองของธุรกิจ, When เลือกบริการ → พนักงาน (หรือคนไหนก็ได้) → เวลาว่าง → กรอกชื่อ/เบอร์โทร → กดยืนยัน, Then ระบบสร้าง booking สถานะ `confirmed` และส่งข้อความยืนยันไปยังช่องทางที่กรอก (อ้างอิง FR-004)
- Given ช่วงเวลาที่เลือกถูกจองไปแล้วโดยลูกค้าอื่นระหว่างกรอกฟอร์ม, When กดยืนยัน, Then ระบบแสดง error ที่เข้าใจง่ายและไม่สร้าง booking ซ้ำ (อ้างอิง BR-001)
- Given พนักงาน A มีนัดทับกับช่วงเวลาที่เลือกอยู่แล้ว, When ลูกค้าเลือกพนักงาน A และบริการที่ใช้เวลาทับกับนัดเดิม, Then ระบบไม่แสดงช่วงเวลานั้นเป็นตัวเลือกว่างตั้งแต่แรก (อ้างอิง FR-005/BR-005)
- Given หน้าจอเปิดบนมือถือหน้าจอเล็ก, When เลื่อนดูตัวเลือกช่วงเวลา, Then ปุ่มเลือกเวลาต้องมีขนาดแตะได้สะดวกและไม่ล้นจอ (อ้างอิง Design Brief — Design Principles)
